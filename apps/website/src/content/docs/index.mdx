A session with an AI model is recorded for evaluation, debugging and analysis.
The conversation alone is rarely enough: you also want the OpenTelemetry spans,
the per-call token and cost metrics, the retrieval scores, the judge outputs.
trajs gives that data a home next to the conversation, without an untyped bag and
without versioning the whole file every time something changes.

## What trajs gives you

<CardGrid stagger>
  <Card title="A trajectory is a stream" icon="list-format">
    A trajectory is an Effect `Stream` of parts, not a document. Prompt parts, response parts and
    extension parts share one total order, so extension data can never be dropped by a combinator
    that only knows about messages.
  </Card>
  <Card title="Extensions are first-class" icon="puzzle">
    Every extension datum carries a namespaced identifier, a semantic version, a schema and an
    optional anchor to the part it is about. Knock-off untyped `extra` bags are not part of the
    model.
  </Card>
  <Card title="Tolerant by design" icon="star">
    Tools outside the toolkit and extensions without an installed definition decode to unconstrained
    parts instead of failing. Loading recorded history does not depend on what is installed today.
  </Card>
  <Card title="Tool calls with their results" icon="information">
    `Toolkit.toolTurns` correlates each recorded tool call with the result that answers it and
    narrows both to the tool's own types.
  </Card>
  <Card title="Rebindable toolkits" icon="laptop">
    A toolkit round-trips through draft-07 JSON Schema, and a recording made against an empty or
    older toolkit is decoded again against the tools it actually refers to.
  </Card>
  <Card title="One interchange format" icon="document">
    A `.trajs` file is newline-delimited JSON: a header first, then one part per line, discriminated
    by `_tag`.
  </Card>
</CardGrid>

## Built on Effect

trajs is built from the same pieces as `effect/ai`: trajectories are `Stream`s,
tools are `Tool`s collected into a `Toolkit`, extensions mirror that shape with
`Extension` and `Extensionkit`, and every failure is a typed error. If you already
model AI sessions with Effect, the vocabulary is the one you know.
