A session with an AI model is recorded for evaluation, debugging and analysis.
trajs records the conversation the model ran on — the messages it was given and
the parts it returned — as a trajectory that stays attached to the toolkit and
metadata it was recorded with, so it can be stored, replayed and inspected.

## What trajs gives you

<CardGrid stagger>
  <Card title="A trajectory is a stream" icon="list-format">
    A trajectory is an Effect `Stream` of parts, not a document. Prompt parts, response parts and
    session declarations share one total order, so nothing is dropped by a combinator that only
    knows about messages.
  </Card>
  <Card title="Tolerant by design" icon="star">
    Tools outside the toolkit decode to unconstrained parts instead of failing. Loading recorded
    history does not depend on what is installed today.
  </Card>
  <Card title="Tool calls with their results" icon="information">
    `Toolkit.toolTurns` correlates each recorded tool call with the result that answers it and
    narrows both to the tool's own types.
  </Card>
  <Card title="Rebindable toolkits" icon="laptop">
    A toolkit round-trips through draft-07 JSON Schema, and a recording made against an empty or
    older toolkit is decoded again against the tools it actually refers to.
  </Card>
  <Card title="One interchange format, two storages" icon="document">
    A `.trajs` file is a header record and one record per part; `Format.jsonl` writes them as lines
    of JSON and `Format.bson` as BSON documents.
  </Card>
</CardGrid>

## Built on Effect

trajs is built from the same pieces as `effect/ai`: trajectories are `Stream`s,
tools are `Tool`s collected into a `Toolkit`, and every failure is a typed error.
If you already model AI sessions with Effect, the vocabulary is the one you know.
